The agent loop

The LLM: a statistical function

  • An LLM is one statistical function that understands a text and predicts what follows.
  • The input text is everything it knows about the task at hand.
  • Billions of parameters hold everything it learned from human text.
  • Chatbots, thinking models and agents are all built on this one function.
  • This chapter shows what “it predicts the next word” means exactly.

The agent loop

Tokenization: encode text for statistics

  • All human text is encoded with one fixed vocabulary of about 256,000 tokens.
  • Tokens are frequent small slices of text rather than words.
  • A rare word is split into several frequent tokens.

The agent loop

Inference: a whole document, one token at a time

The cat sat on the mat while the rain fell. It watched the drops race down the window, then curled up and fell asleep. When the storm passed, it woke, stretched and walked to the door, waiting for someone to let it out…
  • One call reads the whole text so far and predicts the next token.
  • The new token is added to the end of the text before the next call.
  • A whole document takes one call per token.
Demystifying LLMs 5

The agent loop

Chatting: one turn at a time

  • Each time you send a message, the chatbot sends the whole conversation to the LLM.
  • The LLM writes the assistant’s turn token by token, until the end token.
  • The LLM remembers nothing between turns. The conversation it receives is its only memory.
  • A hidden first turn, the system prompt, gives the assistant its instructions.

Tool calling: the answer can be an instruction

UserWill it rain in Paris on Saturday?
Assistantweather(city="Paris", day="Sat")
Chatbot system · runs it, posts the result{"forecast": "rain", "temp_c": 11}
AssistantYes, rain, 11 °C. Plan indoors.
  • The assistant only writes messages.
  • So a message can be an instruction: “call this tool, with these arguments”.
  • The chatbot system runs it and posts the result back as a new message: the LLM executes nothing.
  • The forecast is fetched, not predicted: live context, not training data.

YouTurn the three Q3 reports in data/ into a one-page memo.
Assistant · to the environmentlist_files("data/")
Environmentq3-sales.pdf, q3-ops.pdf, q3-hr.pdf
Assistant · to the environmentread_file("data/q3-sales.pdf")
Environment“Revenue up 12%, margin flat…”
Assistant · to youDone: outputs/memo.md, one page.
  • You talk to the chatbot. The chatbot talks to the environment: files, tools, the internet.
  • The environment runs each instruction and reports back. It is not intelligent.
  • The conversation stops when the next message is addressed to you.

The agent loop

Self-verification: check the result against the goal

  • Observing is not checking: a tool call can succeed and the result still be wrong.
  • One more step in the loop: compare the result to explicit criteria (tests, specs, a checklist).
  • Reasoning alone: plausible plans. Tools alone: unchecked actions. With checks: tested results.
  • It stops when the criteria are met, not after a fixed number of steps.

Software engineering: the ideal sandbox

$ run tests FAIL 3 failed, 41 passed … agent reads the failures, edits the code … $ run tests PASS 44 passed
  • Code gives deterministic feedback: compilers, unit tests, linters.
  • Verification is free, instant, unambiguous: the test passes or fails.
  • Why coding agents matured first, and fuzzier tasks lag behind.
  • Lesson: give the agent a way to check itself.
