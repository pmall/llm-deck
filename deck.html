Part 1 · The Foundation Model

Tokens: How Models Read

  • Text is split into tokens — sub-word units
  • Tokens are how a model reads and represents any input
  • Not words, syllables or characters — whatever fragments the tokeniser found frequent
  • The same sentence costs a different token count in each language
Demystifying LLMs 5

Part 1 · The Foundation Model

Autoregressive Generation

  • Each step yields a probability distribution — a score for every token in the vocabulary
  • The next token is sampled from that distribution
  • The token is appended, and the loop starts again
  • Sampling, not the model, is why one prompt gives different answers

Reflexive Writing, Not a Knowledge Base

  • “Reflexive writing”, conditioned entirely by the prompt

Part 1 · The Foundation Model

Language Disparity in the Data

  • Pre-training data is massively imbalanced — roughly 80% English
  • Consequences for every other language:
    • Quality gap — richer prose, vocabulary and facts in English
    • Cost and context — more tokens for the same text, less room in the window
    • Cultural default — norms, references and examples skew English-speaking
    • Local knowledge — national rules, procedures and jargon are thinner
  • In practice: work in English, then translate — the smaller the language, the bigger the gain

Instruction Tuning & Assistant Alignment

  • Instruction tuning — fine-tuning on instructions paired with ideal assistant responses
  • Pattern reproduction again, at training scale — the pattern is the assistant role
  • It answers instead of continuing, with a stable persona and tone
  • The base model never refused to help — it had no notion of being asked

Reinforcement Learning Horizons

  • Reinforcement learning — answer, get graded, reinforce what scores well
  • RL on verifiable answers — automatic grading on factual data, for accuracy
  • RLHF — humans pick the better of two answers, for tone, helpfulness, safety
  • Two targets: what the model knows, how it behaves

Part 2 · Post-Training

Chat Is Stateless

  • The model remembers nothing between two messages
  • Every API call re-sends the full history
  • KV cache — stores computed attention states, so history is not re-processed
  • Without it, each turn would be slower and costlier than the last
Demystifying LLMs 17

Part 2 · Post-Training

Context Rot: The Long Conversation Trade-off

  • The KV cache makes long chats cheap — nothing pushes you to start over
  • But reasoning degrades as context grows: early instructions fade, contradictions pile up
  • The failure is silent — the model never warns you
  • Daily rules:
    • New topic — new conversation
    • Long thread — restate the goal
    • Documents — keep only what is still relevant

Part 2 · Post-Training

Grounding via Context Injection

  • Parametric memory — writing from what was absorbed in training
  • Context grounding — writing from documents you put in the prompt
  • Same model, same question — only the prompt changes

Tools and Agentic Loops

Part 3 · Tools and Agentic Loops

What Is an “Agent”? Nobody Quite Agrees

  • No settled definition — so agent debates go in circles
  • The model? The software around it? Both? Vendors mean all three
  • What we can define:
    • LLM — the text and reasoning engine
    • Harness — the software around it: tools, loop, state, interface
    • Agent — a degree, not a category: initiative between human interventions
Demystifying LLMs 22

Part 3 · Tools and Agentic Loops

Tool Calling Foundations

  • A model that writes text can write structured tool requests
  • It runs nothing — it writes a request; the software executes and returns the result
  • A three-party exchange: user, agent, and the system answering the agent
  • Two of the three parties are usually invisible to the user
Demystifying LLMs 23

Part 3 · Tools and Agentic Loops

The Self-Referential Execution Flow

  • Instruction Message → Tool Response Message
  • The system talks to itself, in an automated loop
  • Each tool response becomes context for the next instruction
  • One question, many tool calls — until the agent has what it needs

Part 3 · Tools and Agentic Loops

A Weekend in Paris

  • “Plan me a weekend in Paris in two weeks. I like museums; max twenty minutes’ walk between stops.”
  • What the agent must fetch first:
    • Weather — forecast for those dates: indoors or outdoors
    • Places — museums, restaurants, opening hours
    • Routing — real walking times between stops
  • None of it is in the model — all of it is fetched, then reasoned over

Computer Use: When There Is No API

  • No API? The agent uses software like a person: read, point, click, type
  • Unlocks the long tail — legacy apps, web interfaces, anything never integrated
  • Slower, more fragile, costlier — interfaces change, the agent must re-orient
  • Not a superpower: a fallback for what was never machine-readable

Part 3 · Tools and Agentic Loops

Code Execution

  • The agent writes code, runs it in a sandbox, uses the result
  • Why code? Where a model is weak, code is exact:
    • Volume — 5,000 rows fit in context, but row 4,000 won’t get row 12’s care
    • Arithmetic — exact totals and rates, not plausible-looking numbers
    • Repeatability — same script, next month’s file, auditable line by line
    • Orchestration — looping, chaining and recovering tool calls
  • Plus structured data parsing and precise tool execution

Part 3 · Tools and Agentic Loops

Dynamic Instructions (Skills)

  • Procedures, domain rules and templates, loaded on the fly
  • Retrieval injects data; skills inject instructions — the how, not the what
  • E.g. report format, pre-publication checklist, filing conventions, monthly close, tone rules
  • Loaded only when relevant — short standing instructions, less context rot
Demystifying LLMs 30

Part 3 · Tools and Agentic Loops

The ReAct Loop

  • Think → Act → Inspect → Adjust, until validation criteria are met
  • Reasoning to plan, tools to act, verification to check against the goal
  • Reasoning alone: plausible plans. Tools alone: unchecked actions. The loop: tested results
  • Stops when the criteria are met — not after a fixed number of steps
