Demystifying LLMs 8

Part 1 · The foundation model

The model is a function: f(x) = y

f(token1 . token2) = distribution → token3
  • x — the input: a sequence of tokens, the text so far
  • y — the output: a probability distribution, one score for every token in the vocabulary
  • That is the whole interface. Nothing else goes in.
f(“I drank a delicious cup of”) =
coffee42%
tea28%
matcha9%
cacao6%
… thousands15%

Demystifying LLMs 9

Part 1 · The foundation model

Generating text is calling f again

f(token1 . token2) = distribution → token3 f(token1 . token2 . token3) = distribution → token4 f(token1 . token2 . token3 . token4) = …
  • The next token is sampled from the distribution
  • The token is appended to x, and the loop starts again
  • Sampling, not the model, is why one prompt gives different answers
Lore

GPT = Generative Pre-trained Transformer — the architecture comes from “Attention Is All You Need” (2017).

Judge the document, not the mechanism

The worry

“It only predicts the next word.”

True — and it makes people freak out. It tells you nothing about the quality of what comes out.

The question that matters

Is the produced document good?

Useful, correct, fit for the task — that is what we evaluate, and what the rest of this talk builds on.

How the document gets written can change — other architectures exist, such as diffusion text models. Nothing that follows would change.

What each API call carries
Turn 1

Part 2 · Tools

Tool calling: the model writes, software runs

UserWill it rain in Paris on Saturday?
Assistant → systemweather(city="Paris", day="Sat")
System → assistant{"forecast": "rain", "temp_c": 11}
Assistant → userYes — rain, 11 °C. Plan indoors.
f(system . user . tool_call . tool_result) = assistant
  • A model that writes text can write structured tool requests
  • It runs nothing — it writes a request; the software executes and returns the result
  • A three-party exchange: user, agent, system — two of them usually invisible to you
Lore

The ReAct loop and self-verification

Thinkplan
→
Actcall a tool
→
Inspectcheck against the goal
→
Adjustfix, or stop
↺

until the validation criteria are met

  • Reasoning to plan, tools to act, verification to check against the goal
  • Reasoning alone: plausible plans. Tools alone: unchecked actions. The loop: tested results
  • The agent verifies its own result — and stops when the criteria are met, not after a fixed number of steps
Lore
