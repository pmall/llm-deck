Tool calling: the answer can be an instruction

UserWill it rain in Paris on Saturday?
Assistantweather(city="Paris", day="Sat")
Chatbot system · runs it, posts the result{"forecast": "rain", "temp_c": 11}
AssistantYes, rain, 11 °C. Plan indoors.
  • The assistant only writes messages
  • So a message can be an instruction: “call this tool, with these arguments”
  • The chatbot system runs it and posts the result back as a new message: the LLM executes nothing
  • The forecast is fetched, not predicted: live context, not training data

The ReAct loop: the Part 1 chatbot, with one rule changed

llm(… user) = tool_call₁ llm(… tool_call₁ result₁) = tool_call₂ llm(… tool_call₂ result₂) = answer

After every answer, it stops: your turn.

Agent

A tool call? Run it, append the result, call the LLM again. It stops only when the LLM answers.

Part 2 · How an agent works

Self-verification: check the result against the goal

  • Observing is not checking: a tool call can succeed and the result still be wrong
  • One more step in the loop: compare the result to explicit criteria (tests, specs, a checklist)
  • Reasoning alone: plausible plans. Tools alone: unchecked actions. With checks: tested results
  • It stops when the criteria are met, not after a fixed number of steps
Lore

AutoGPT (2023) made the loop go viral, before LLMs were reliable enough to check their own work.

Software engineering: the ideal sandbox

$ run tests FAIL 3 failed, 41 passed … agent reads the failures, edits the code … $ run tests PASS 44 passed
  • Code gives deterministic feedback: compilers, unit tests, linters
  • Verification is free, instant, unambiguous: the test passes or fails
  • Why coding agents matured first, and fuzzier tasks lag behind
  • Lesson: give the agent a way to check itself

The memo again: now you take zero steps

user › Turn the three Q3 reports in data/ into a one-page memo, with exact figures. list_files("data/") → q3-sales.pdf, q3-ops.pdf, q3-hr.pdf read_file("data/q3-sales.pdf") → “Revenue up 12%, margin flat…” read_file("data/q3-ops.pdf") → “Two sites delayed to Q4…” read_file("data/q3-hr.pdf") → “Hiring freeze lifted…” run_code("check_totals.py") → 2 figures off: fixed write_file("outputs/memo.md") → ok agent › Done: outputs/memo.md, one page, each point sourced.
  • Your five steps are now six tool calls, no human in between
  • List, read, write, run: the basic tools of any agent, checking included
  • The deliverable is a file in the workspace, not a message in the chat

Code execution: where the LLM is weak, code is exact

The LLM estimates

The script computes

Volume

Part 2 · Where it is heading

The open problem: misalignment

Reward hacking

The score, not the intent

A boat-racing agent looped to farm points instead of finishing (CoastRunners, 2016). Coding agents special-case the tests.

Sycophancy

Tells you what you want to hear

Trained on human approval. An update was rolled back in April 2025 for being too flattering.

Agentic misalignment

Conflicting goals, real tools

In simulated companies, some LLMs chose blackmail to avoid being replaced (Anthropic, 2025).

The more autonomy, tools and task length we give, the more it matters: self-verification is only as good as the criteria you set.
